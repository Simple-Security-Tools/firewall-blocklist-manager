1) DONE — blocks wider than /16 refused, /23-/16 require typed confirmation

3) Note that you cannot create a named location with no entries. You always need 1 entry to initialize it.

4) DONE - carve-out subtracts as before AND records an ALLOW for the carved
   range. Carving worked under DENY_ONLY all along, since remove has no
   deny_mode gate; what was missing was anything for the allow list to publish.
   The covering BLOCK is still replaced by the CIDRs around the hole, so the
   block list and the Named Location are unchanged and no firewall rule
   ordering is relied on. The ALLOW row is a record of the exception, inherits
   the covering rule's expiry, and stays put if the surrounding blocks are
   removed by hand. See "Lifetime of the ALLOW record" in DOCUMENTATION.md.

5) DONE - sync publishes a placeholder when no rules are active. It used to
   bail before calling Graph, so Entra kept enforcing the last list it was
   given while the tool reported no active rules: a partner locked out, and
   list showing nothing to explain why. Entra rejects an empty Named Location,
   so the empty state is published as 192.0.2.0/24, RFC 5737 documentation
   space that is not globally routable and matches nobody. No wipe step is
   needed to undo it, since the PATCH replaces the whole collection and the
   next sync carrying real rules removes it.

6) IPv6 sync is broken upstream. microsoft_graph_helpers builds every ipRanges
   entry as "@odata.type": "#microsoft.graph.iPv4CidrRange", so an IPv6 CIDR
   goes to Graph mislabelled and should be rejected, failing the whole PATCH.
   Everything else handles IPv6 correctly, including the block list export, so
   this only affects sync. Fix belongs in microsoft_graph_helpers: choose the
   odata type per entry from ipaddress.ip_network(cidr).version. Noted in the
   README until then. Untested against a live tenant.
